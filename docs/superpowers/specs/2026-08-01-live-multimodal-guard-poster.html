Live Multimodal Guard — Architecture Poster

Full-scope context sheet · new parallel "Live mode" for the AI Guard · Rioc + web-ui · 2026-08-01

GPU · central

Omni Streaming Server
  • Holds one stateful MiniCPM-o omni session per conversation
  • streaming_prefill ingests ~1s video+audio chunks
  • streaming_generate emits streaming speech + text
  • Generation edge-triggered (user_speech_end), not server VAD
  • interrupt → abort generate, keep prefilling

GPU pool · control plane

Session Router
  • POST /allocate → least-loaded healthy GPU, under a lease
  • Returns gpu_ws_url + token — Rioc connects direct
  • No media proxied — router is control-plane only
  • Static pool · fleet ceiling K = Σ kᵢ · add GPUs → K grows
  • capacity_exhausted only when the whole pool is full

GPU · per-instance cap

Admission Control
  • Per-GPU capacity kᵢ = that GPU's measured real-time ceiling (>1)
  • Grants or returns capacity_exhausted (router-race backstop)
  • Cap protects each GPU's latency / barge-in — not a limit-to-one
  • Reports occupancy to the router · emits in-use metric

LAN · Rioc

Live Session Orchestrator
  • live_session.py · sibling of ConversationManager
  • Owns WS client + escalation-overlay timer
  • Wires camera + mic + VAD + speaker to the channel
  • Selected when CONVERSATION_MODE=live

LAN · Rioc

Edge VAD + Barge-in Controller
  • Extends mic_listener.py · webrtcvad continuous
  • Emits user_speech_start / user_speech_end upstream
  • Barge-in: local flush+stop and upstream interrupt
  • Reference-signal gating vs. guard's own voice (MVP)

LAN · Rioc

Real-time Speaker Sink
  • Extends existing WebSocket G.711 path in _guarded_play
  • Plays a stream of chunks + 200–400ms jitter buffer
  • flush-and-stop-now primitive for barge-in
  • Streaming resample → 8kHz μ-law · WS speaker required

Transport + UI

Live channel + Live Tab
  • Versioned bidi WebSocket · seq + ts
  • SSE relay /live/stream → web-ui captions/state
  • Live Tab: video, captions, indicators, capacity banner
  • UI gated behind prototype-first-ui sign-off

Guardrails / safety

Failure is visible, never silent
  • capacity_exhausted → UI banner + event log + metric
  • WS/GPU drop → stop speaker, outcome Error, surfaced
  • No auto-fallback — operator switches to turn-based manually
  • Live mode + URL-only speaker → config refused
  • False barge-in → guard re-generates (acceptable)

Architectural principles

Held invariants
  • Barge-in decision stays at the edge (no WAN in the loop)
  • Rioc remains the LAN media hub (appliance model intact)
  • Live path is MiniCPM-o end-to-end (no Whisper/TTS on it)
  • Turn-based engine untouched + coexisting
  • One responsibility per unit · defined WS/SSE interfaces

Out of scope (this iteration)

Deliberately not building
  • Elastic GPU autoscaling (static multi-GPU pool IS in scope)
  • Auto fallback live → turn-based
  • Full acoustic echo cancellation
  • Multi-camera / multi-speaker per session
  • Replacing the turn-based engine
